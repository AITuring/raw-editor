# RAW Editor

一个面向个人摄影工作流的、跨平台、非破坏性 RAW 编辑器。

本项目以 [RapidRAW](https://github.com/CyberTimon/RapidRAW) 为上游基础，在接受并遵守
AGPL-3.0 的前提下继续开发。现阶段不追求 AI 功能，也不追求与 Adobe Camera Raw
像素级完全一致；目标是先实现一套画质可靠、响应流畅、可以每天使用，并且核心摄影
工作流与 Camera Raw 基本一致的非 AI RAW 编辑器。
上游来源与再发行声明见 [NOTICE](NOTICE)。

## 项目目标

首个正式目标是完成 **Daily RAW 1.0**：

- 支持常见 RAW 文件的可靠导入、预览、编辑和导出，首要测试机型为 Sony α7R V。
- 从打开 RAW 到导出成片，全程保持非破坏编辑，绝不修改原始文件。
- 覆盖 Camera Raw 的核心非 AI 摄影流程：
  - 相机配置文件、白平衡和基础影调；
  - 曲线、HSL、颜色分级和黑白；
  - 锐化、亮度降噪、颜色降噪；
  - 镜头校正、裁剪、旋转、拉直和透视；
  - 画笔、线性渐变、径向渐变、颜色范围和明度范围蒙版；
  - 修复、仿制、预设、历史、快照、复制/同步设置；
  - 胶片栏、批量编辑、后台导出和色彩管理。
- 在 60MP RAW 上仍能流畅调整参数、查看 100% 细节并稳定导出。
- macOS 作为首要开发平台，同时维持 Windows 和 Linux 的可构建性。

“与 Camera Raw 基本一致”指功能结构、编辑语义和日常操作流程一致，不代表复刻 Adobe
界面，也不要求使用同一参数值后得到完全相同的像素。Adobe 的相机配置文件、色彩算法
和处理模型并不开源，本项目将通过公开标准、开源算法和自己的回归样片建立独立画质基线。

## 当前基础版本

当前仓库已经合并 RapidRAW 上游代码，并保留 `rapidraw-upstream` 远程用于里程碑边界同步。
应用身份已切换为 RAW Editor，默认启用 `basic` 模式：保留 RAW 导入、预览、全局调整、裁剪、
非 AI 蒙版、sidecar 和导出主链路。旧版浏览器编辑器的 `ImageState` 参数模型通过
`src/basic/legacyAdjustmentAdapter.ts` 映射到 RapidRAW 的原生 `Adjustments`，因此后续可以
继续复用旧页面的参数语义，而不再依赖旧的 WebGL/浏览器 RAW 解码器。

应用现已固定为纯本地产品：没有账号或登录、社区与在线预设、云端处理、远程 AI connector、
在线地图、自动更新检查和遥测，也不会把照片、EXIF、编辑参数或提示词上传到服务器。公开开源
依赖不在此限制内：构建时可以从公共源获取依赖，用户明确启用本地模型能力时也可以下载
ONNX Runtime 或公开模型到应用私有数据目录；推理由本机完成。依赖与模型也可以预先打包，
准备完成后核心编辑流程不要求联网。

编辑数据统一写入应用私有数据目录的 `sidecars-v1`，不再在照片文件夹旁生成 `.rrdata` 等内部
文件。首次遇到旧版相邻 sidecar 时会先原子迁移到私有目录，确认成功后删除旧文件。Daily RAW 1.0
格式契约见 [`schemas/sidecar-v1.schema.json`](schemas/sidecar-v1.schema.json)。

本地运行：

```bash
npm install
npm run dev              # 仅启动 Vite 前端
npm run start            # Tauri 2 开发窗口
```

`VITE_RAW_EDITOR_MODE=full` 只用于后续调试上游完整面板；日常开发保持默认的 basic 模式。
需要构建或打包本地 ONNX 功能时，显式设置 `RAW_EDITOR_ENABLE_AI_RUNTIME=1`；默认构建不会
预取或打包 ONNX Runtime。该开关只允许获取公开运行时，不会启用任何云端产品能力。

## 1.0 范围

### 必须完成

#### RAW 与色彩管线

- RAW 解包、黑电平、白电平、坏点处理和方向信息。
- Bayer 与 X-Trans 基础支持。
- 相机白平衡、自定义色温/色调和白平衡拾色器。

- 32 位 scene-linear 内部工作空间。
- 显示器 ICC 转换、软打样基础能力和导出 ICC 嵌入。
- 高质量全分辨率分块导出，预览和导出使用同一参数语义。

- 锐化数量、半径、细节和蒙版。
- 亮度降噪、亮度细节、颜色降噪和颜色细节。
- 暗角、颗粒等基础效果。

- Lensfun 自动匹配镜头。
- 畸变、暗角、横向色差和紫边校正。

- 局部曝光、影调、白平衡、颜色、清晰度、去雾、锐化和降噪。

## 完成标准

Daily RAW 1.0 只有同时满足以下条件才算完成：

- 原始 RAW 文件在全部编辑、退出、崩溃恢复和导出流程中保持字节不变。
- 关闭应用后重新打开，sidecar 能完整恢复全局参数、裁剪、蒙版、历史关键点和输出设置。
- 预览与全分辨率导出不存在明显的颜色、裁剪、蒙版边缘或锐化差异。
- α7R V 60MP ARW 可以完成连续导入、编辑、切换、100% 查看和导出，不崩溃、不产生空白图。
- 常用滑块在指定测试 Mac 上以交互预览运行，目标为 P95 更新延迟不超过 33ms。
- 使用嵌入缩略图时首屏目标小于 1 秒；可编辑预览目标小于 3 秒。
- 缓存后的相邻照片切换目标小于 500ms。
- 批量导出 100 张混合 RAW 时，单张失败不会中止队列，并能看到文件级错误和重试入口。
- JPEG 和 TIFF 带正确 ICC；重新打开导出文件后颜色与应用预览一致。
- macOS 发布构建通过；Windows、Linux 至少通过 CI 构建和核心渲染回归测试。
- 不需要网络即可完成 1.0 的全部编辑功能。

性能数字是工程预算，不是牺牲画质的理由。如果目标机器或测试素材变化，需要在基准报告中
记录新条件，而不是静默降低输出质量。

## 技术方向

沿用并强化 RapidRAW 已验证的技术路线：

- 应用壳：Tauri 2。
- 前端：React、TypeScript、Vite。
- 核心：Rust，耗时任务放入后台工作线程，禁止阻塞 UI。
- GPU：WGPU + WGSL，使用 32 位 scene-linear 处理。
- RAW：保留可替换的解码器接口；先使用 RapidRAW/rawler 现有能力，必要时补充 LibRaw
  或 RawSpeed 后备。
- 镜头：Lensfun。
- ICC：优先接入 LittleCMS。
- 数据：版本化 JSON 编辑数据统一保存在应用私有数据目录；SQLite 保存索引、缩略图、评分和队列状态，不在照片目录生成内部文件。
- 输出：原生分块渲染和编码，不通过 WebView IPC、JSON 或 Base64 传输整张图。
- AI：1.0 默认不启用；后续能力只接受公开模型的可选下载或本地打包，并且只在本机推理。

处理管线必须保持明确顺序，不能继续演变成一个难以验证的超大 shader：

```text
RAW 解包
  -> 黑白电平 / 坏点
  -> 镜头预校正和色差
  -> 白平衡
  -> 去马赛克
  -> 高光恢复
  -> 相机配置文件
  -> scene-linear 工作空间
  -> 全局影调与颜色
  -> 局部蒙版与修复
  -> 输出效果和锐化
  -> 显示 ICC 或导出 ICC
```

每个节点都必须声明：

- 输入、输出颜色空间和数值范围；
- 是否依赖完整分辨率或邻域像素；
- 是否支持分块和 ROI；
- 是否能在 GPU 和参考实现之间做结果对照；
- 参数版本以及 sidecar 迁移规则。

## 日常开发流程

### 1. 开始一个功能

1. 从 `main` 创建短生命周期分支：`codex/<milestone>-<feature>`。
2. 在 issue 或任务说明中写清用户场景、输入、输出、非目标和验收样片。
3. 明确处理节点位置、颜色空间、分辨率层级、sidecar 字段和许可证影响。
4. 先补测试或基准，再实现功能。

### 2. 实现

1. 参数 schema、Rust 核心、WGSL、前端控件和 sidecar 序列化必须作为一个闭环实现。
2. 预览不得采用导出时无法复现的临时算法。
3. UI 只传参数、任务状态和小型统计数据；完整像素留在原生内存或 GPU。
4. 所有长任务必须可取消，并提供进度、文件名和明确错误。
5. 修改管线顺序、色彩空间或默认参数时，必须增加 sidecar 版本或迁移规则。

### 3. 验证

每个图像处理变更至少完成：

- 单元测试：参数边界、矩阵、坐标变换、sidecar round-trip。
- GPU/CPU 或参考输出对照。
- 小图、60MP 图、横竖方向、裁剪、旋转和带蒙版导出。
- α7R V 基准样片人工检查。
- 性能记录：首屏、可编辑预览、滑块延迟、100% ROI、导出、峰值内存。
- `git diff --check`、Rust 格式化、TypeScript 检查、lint 和测试。

不能只凭编译成功或缩略图正常就宣布修复。涉及导出的修改必须检查实际导出文件；涉及
高分辨率性能的修改必须使用真实 60MP RAW。

### 4. 合并

合并前必须审查：

- 功能逻辑和边界情况；
- 预览/导出一致性；
- 性能和内存；
- 可访问性和响应式布局；
- 文件路径、元数据和不可信 RAW 的安全处理；
- 许可证和第三方声明；
- 是否意外改变旧 sidecar 或默认成像结果。

`main` 必须始终保持可构建、可启动、可打开基准 RAW、可导出。上游 RapidRAW 的更新只在
里程碑边界集中同步；同步后先完整跑基准，再开始下一个功能，避免开发中途持续漂移。

## 测试素材与画质基线

测试集至少包含：

- α7R V：日光、阴天、钨丝灯、混合光、人像肤色、红色展品、蓝紫灯光。
- ISO 100、ISO 1600、ISO 6400 及更高 ISO。
- 正常曝光、欠曝 2–4 档、局部高光剪切。
- 高反差建筑、细密纹理、树叶、织物、星点和重复图案。
- 明显桶形/枕形畸变、暗角、横向色差和紫边。
- Bayer、X-Trans、DNG，以及损坏或截断文件。
- 横图、竖图、不同裁剪、旋转和多层蒙版。

大型 RAW 不直接提交到 Git 仓库。仓库保存素材清单、相机信息、许可、校验值、预期输出
版本和获取方式。基准导出需要记录处理引擎版本、GPU、操作系统和参数 sidecar。

画质对照使用 Camera Raw、darktable 和 RawTherapee 的代表性导出，但不以单一 SSIM/PSNR
作为正确标准。检查内容包括中性灰、肤色、饱和色、高光过渡、暗部色偏、细节、噪声、
摩尔纹、锐化光晕、镜头边缘和蒙版边界。

## 发布原则

- 原片安全优先于功能数量。
- 预览和导出一致优先于单纯追求预览速度。
- 真实相机样片优先于合成 demo。
- 非 AI 核心稳定前不扩张本地 AI；云端、账号和社区能力不进入产品规划。
- 不复制 Camera Raw 的品牌、图标或界面；对齐的是工作流和摄影能力。
- 每次发布附带支持机型、已知限制、性能基准、迁移说明和完整对应源代码。
