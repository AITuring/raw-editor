# 当前焦点堆栈算法说明

本文描述 RAW Editor 当前 `BlendMode::FocusStack` 的实现状态，重点说明它在平面画面、
手机多角度拍摄、混合 35mm/85mm 焦段和不同景深层之间的处理方式。

本文记录的是当前分支 `codex/image-stack-alignment-robust` 的工程能力和已知边界，
不是对所有输入都成立的数学完美性保证。

## 结论先说

在“同一画面、足够重叠、画面基本平面、每个位置至少有一张清晰照片”的前提下，
当前算法已经具备生成全图清晰堆栈的主要技术路径：

- 用平面单应性处理拍摄角度变化；
- 用局部和原生分辨率细化修正残余错位；
- 用清晰度与像素不一致性共同决定每个区域由哪一张源图负责；
- 对细节采用硬 ownership，不把两个错位的清晰笔画平均成模糊双影；
- 对混合焦段使用 EXIF 焦距约束、分组渲染和更严格的局部融合；
- 对没有验证重叠的图片拒绝生成“看起来完整”的结果。

但当前还不能宣称“任意输入都百分之百无重影、百分之百每个像素都清晰”。
算法没有正式的逐像素证明系统，也没有把所有视觉伪影都自动判定为失败的质量门槛。

## 处理流程

### 1. 图像准备和分析

每张输入图像会先被解码为浮点 RGB 图像，同时生成用于对齐的灰度分析图。焦点堆栈还会
额外提取：

- BRIEF 特征和描述子；
- 前景/高梯度区域；
- 水平、垂直长边候选；
- 前景特征点；
- EXIF 35mm 等效焦距（如果元数据存在）。

大堆栈会使用受限的分析尺寸和有界 worker 数，避免一次性为所有高分辨率图像建立过大的
临时内存。

### 2. 成对匹配和几何模型选择

焦点堆栈匹配不是只依赖文件名或导入顺序。程序会从图像证据中寻找对应关系，并使用
RANSAC 和对称重投影误差筛选稳定模型。候选模型包括：

- 平移；
- 相似变换；
- 仿射变换；
- 平面投影/单应性。

当照片存在角度变化、缩放变化或镜头模块变化时，焦点堆栈路径允许使用投影模型。
局部匹配还会使用 NCC/patch refinement，并要求反向检查和邻域一致性，减少重复笔画或
重复纹理把局部模型拉到错误位置。

混合焦段边会额外检查：

- EXIF 焦距比例是否和变换缩放大致一致；
- 是否有足够的内点；
- 中位对称误差是否足够小；
- 是否有足够前景支持。

不满足条件的混合焦段“桥接边”会被拒绝，避免把两个独立区域错误连起来。

### 3. 自动排序和全局对齐

焦点堆栈会根据匹配图构建连续路径，而不是盲目按照文件选择顺序叠放。

- 不超过 64 张的焦点堆栈优先执行全成对搜索；
- 更大的堆栈使用有界的邻近候选和视觉检索；
- 全局注册使用鲁棒迭代，降低少量错误匹配的影响；
- 如果有图片没有验证过的重叠，程序会拒绝完整输出，并提示选择连续场景或增加重叠。

这一步解决的是“哪些图属于同一个连续场景、各图大致落在哪里”，不负责最终的细节
清晰度选择。

### 4. 自动选择两条融合路径

程序会根据帧间位移、缩放、旋转、画幅变化和焦距变化判断当前堆栈属于哪种情况。

#### 普通焦点堆栈

当各帧基本是同一画幅，只是焦点深度不同，使用标准 focus-stack 路径：

1. 生成每层的焦点评分图；
2. 只在有有效来源的区域切换 ownership；
3. 前景/遮挡区域优先保持已经确认的 ownership；
4. 通过全分辨率决策覆盖低分辨率分析决策；
5. 细节像素硬选择，不对错位的细节做整图平均；
6. 只对背景画布的低频色调做有限的颜色协调。

#### 位移、斜拍或混合焦段的 shifted mosaic

当相机位置或焦段变化使画面成为“带焦点差异的平面拼接”时，使用
`detail_preserving_mosaic`：

1. 每一层先做两轮分析分辨率局部配准；
2. 再做原生分辨率 patch refinement；
3. 对每个候选区域计算清晰度（acutance）；
4. 同时计算候选与当前底图的像素不一致性；
5. 用图割求解 ownership，让接缝绕开高对比笔画；
6. 对候选错位的锐利区域增加不一致性惩罚；
7. 对透视缩小的 telephoto 图像先做预滤波，避免纹理混叠伪装成清晰；
8. 最终直接复制被选中的源像素，而不是对两个错位细节做平均；
9. 输出裁切到完全有源图覆盖的有效矩形。

当前 ownership 网格最长边为 512。旧的 320 网格在约 24k 宽画布上会形成约 75px 的
粗块，足以把一根毛笔画完整包进一个错误候选块；现在的细网格和不一致惩罚就是针对这类
矩形重影。

## 当前优势

### 1. 能处理平面画面的拍摄角度变化

对基本平面的纸张、画作、碑帖、屏幕等画面，角度变化主要表现为投影关系。
当前算法可以使用单应性来处理透视，而不要求每张照片像素级平移对齐。

### 2. 不用“平均”掩盖错位细节

传统平均融合在两张图只差几像素时会把笔画、边缘和细线平均成虚影。当前焦点堆栈在
细节 ownership 上采用硬选择，目标是“一处细节由一个真实源图负责”，而不是把两条错位
笔画叠成一条模糊笔画。

### 3. 全局、局部、原生分辨率三级对齐

全局单应性负责稳定框架，局部 patch refinement 负责吸收小范围残差，原生分辨率 refinement
负责修正分析缩小后无法看见的细小错位。对于手机拍摄的高分辨率书画，后两级很重要。

### 4. 对混合 35mm/85mm 有专门保护

混合焦段不会被当成普通同焦距序列简单叠放。当前实现会：

- 读取并利用 EXIF 焦距提示；
- 对混合焦段匹配设置更严格的尺度和内点要求；
- 对渲染顺序按焦距分组，让 telephoto 细节在有覆盖时优先；
- 在局部 ownership 中避免宽角图重新夺回已经确认的细节块。

这正是题跋测试中“粗块重影”问题的主要修复方向。

### 5. 对错误场景有拒绝机制

没有验证重叠的图不会被静默塞进结果。对于独立场景、重叠不足或匹配图不连通的输入，
程序会返回错误，而不是生成一张包含未知断裂区域的成片。

### 6. 输出像素可追溯到真实源图

当前算法不做 AI 补画，不凭空生成笔画。shifted mosaic 路径最终的有效矩形中，每个像素
都有一个源图 ownership；每个像素要么来自某张输入图的重采样，要么来自受限的颜色/几何
处理。

这里的“真实来源”不等于“未经重采样”：透视变换、双线性/高质量采样和有限色调校正仍然
可能改变像素数值，但不会创造新的语义内容。

### 7. 有真实样本回归

当前分支已经做过以下本地验收：

| 样本 | 结果 |
| --- | --- |
| `Photos-1-001/题跋`，混合焦段 | 9/9 张进入结果；输出约 `24040×21522`；有效矩形每个像素都有 source ownership |
| `夜宴第三幕`，纯 85mm 子集 | 6/6 张进入结果；输出 `37617×12253`；所有像素都有来源 |
| Rust library tests | `198 passed, 0 failed, 19 ignored` |

其中题跋红框笔画区域做过高分辨率局部检查，未再观察到原先那种明显的双笔画矩形重影。
这属于已验证样本的证据，不是对任意未来输入的绝对保证。

## 当前不足和风险

### 1. 仍然依赖“基本平面”假设

如果画面存在明显弯曲、装裱起伏、纸张褶皱、近距离视差或不同深度层，单一全局单应性
无法精确描述整个画面。当前的局部残差场和边缘 band warp 可以吸收小变形，但不是完整的
非刚性配准或分层 3D 重建。

### 2. 移动物体、反光和内容变化无法被可靠恢复

人物移动、手遮挡、镜面反光、闪光变化、纸面被翻动或纹理本身变化时，图像之间并不存在
一个唯一正确的对应像素。算法只能选择看起来更可信的一层，不能凭空判断哪个瞬间才是“真实
目标状态”。

### 3. 清晰度选择仍是启发式，不是形式化证明

acutance、NCC、前景 mask 和不一致性惩罚能显著减少重影，但它们不是“这个像素一定清晰”
的证明。低纹理区域、细弱墨线、重复纹理、压缩噪声和传感器锐化都可能影响评分。

当前没有完整的逐像素质量置信度图，也没有在导出前自动扫描所有笔画边缘并以“发现任意疑似
重影就拒绝导出”作为硬门槛。

### 4. 硬 ownership 的代价是接缝可能可见

硬选源图能保护笔画不重影，但在曝光、白平衡、阴影或纸张颜色变化较大时，接缝两侧可能
出现轻微色调阶差。当前只对背景画布做低频色调协调，前景笔画保持源图细节，不能保证所有
照明变化都完全不可见。

### 5. 标准路径的边缘填充不是新的实拍内容

普通 focus-stack 路径最后会尝试填充投影后暴露的无效边缘。填充使用邻近有效边缘的反射/
延拓纹理，目的是避免输出出现空洞；它不是来自另一张照片的独立观测，也不应被理解为
新的画面内容。

shifted mosaic 路径更严格：它会裁切到完全有源图覆盖的有效矩形。若需要“所有输出像素
必须直接来自照片、禁止任何边缘延拓”，应优先使用该路径的有效矩形策略，或后续增加透明/
裁切导出选项。

### 6. 混合焦段处理依赖可靠元数据

EXIF 焦距缺失、被手机厂商写错、裁切模块被错误标记时，混合焦段检测和渲染分组会变弱。
图像证据仍会参与匹配，但不能完全替代正确的镜头信息。

### 7. 大于 64 张时搜索是有界的

不超过 64 张的焦点堆栈可以做全成对搜索；更大的选择会切换到有界候选搜索，以控制时间
和内存。这意味着极端乱序、相邻图重叠很弱、但远距离图像有关键对应关系的超大堆栈，可能
被保守拒绝或无法找到最佳顺序。

### 8. 当前验证样本仍然有限

目前已经验证了题跋混合焦段和夜宴纯 85mm 子集，但没有把 `夜宴第三幕` 的全部 69 张照片
作为一个单独场景一次性验收，也没有建立自动化的“重影/清晰度/接缝可见度”图像质量评分。
因此现阶段证据是“关键路径已被真实样本击穿并修复”，还不是完整数据集覆盖。

### 9. 细网格提高了计算量

ownership 网格从 320 提高到 512 能减少大块接缝，但图割节点数和局部采样量会增加。
高分辨率手机照片的真实堆栈仍可能需要较长时间和较大内存，尤其是混合焦段、透视变化和
原生分辨率 refinement 同时启用时。

## 输入建议

若希望最大化“整张都清晰、没有双影”的成功率，建议：

1. 所有照片只包含同一个连续画面；
2. 相邻照片保持足够重叠，并尽量让每个位置在至少两张照片中出现；
3. 画面尽量平整，避免纸面弯曲和近距离前后景视差；
4. 拍摄过程中不要移动原件、相机或光源；
5. 保留原始 EXIF，尤其不要丢失焦距信息；
6. 曝光、白平衡和对焦顺序尽量稳定；
7. 如果输入包含多个独立场景，分组后分别堆栈；
8. 如果必须使用 35mm 和 85mm 混合照片，确保两组之间有宽阔、纹理丰富且真实重叠的桥接区域。

## 后续优先级

为了把当前“已验证可靠”继续推进到“可自动判定质量”，后续最值得做的是：

1. 生成逐像素/逐块的对齐置信度、清晰度和 source ownership 诊断图；
2. 增加笔画边缘重影检测，并把超过阈值的结果阻止导出；
3. 对纸张轻微弯曲增加分块单应性或受约束的非刚性模型；
4. 为边缘无源区域提供“严格裁切 / 透明输出 / 反射填充”三种明确策略；
5. 扩大真实样本回归，覆盖完整 `夜宴第三幕`、不同光线和不同手机镜头组合；
6. 将当前高分辨率局部检查转成自动化图像质量门槛，而不只依赖人工观察。
